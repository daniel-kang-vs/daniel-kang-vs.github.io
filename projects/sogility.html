Athlete Scoring — Sogility

How can a training score explain both peer standing and progress without penalizing younger athletes?

A dual scoring framework separates cohort-relative scores from performance bands, with inspectable Python logic and reproducible synthetic checks.

The problem

A global drill score compares young players with older athletes and obscures what to train next. Small cohorts and noisy repeat attempts make a raw rank unstable.

Data & scope

The analysis used an internal session extract. The public repository contains importable RPS and APS code, synthetic test fixtures, and a validation log. Player-level records and internal interfaces are excluded.

How it works

  1. Normalize drill direction and skew before comparing results.
  2. Fit RPS to age-and-gender cohorts; below 30 observations, use the same age group across genders. Invalid parameters fall back to global benchmarks.
  3. Weight the three most recent attempts 0.5, 0.3 and 0.2.
  4. Compute APS from q30, q50, q70 and q90 anchors on a 0–100 scale; aggregate recent attempts and skill categories to assign a band.

Key technical decision

Keep the displayed RPS separate from the APS performance band. RPS uses all attempts to fit benchmarks; APS uses each player’s latest result per assessment. APS anchors currently refresh with the data; versioned benchmarks would be needed to keep bands stable over time.

Result & interpretation

What the evidence shows

The framework explains one athlete through a peer-relative score and a separate performance band. Parent views emphasize progress and five skills; trainer views emphasize entry, comparison, and history. The repository now exposes the scoring logic, checks, and remaining limitations.

Inside the Python implementation

Two complementary calculations make the score explainable. RPS answers how an attempt compares with its reference group; APS maps assessment results to a performance band. Neither is a prediction of match performance.

RPS · cohort-adjusted sigmoid

The cohort median maps to 64.5 on the 30–99 scale. This is a smooth relative score, not an empirical percentile rank.

z = 1.0986 * (x - median) / abs(span - median)
score = 30 + 69 / (1 + np.exp(-np.clip(z, -700, 700)))

Use the latest three attempt scores at 50% / 30% / 20%; two attempts use 2/3 and 1/3. Average assessment scores for the player summary.

APS · benchmark anchors and performance bands

For higher-is-better drills, benchmark quantiles map directly to score anchors. Lower-is-better handling is documented as a review item.

# Higher-is-better anchor mapping
# q30 → 30, q50 → 50, q70 → 70, q90 → 90
aps = y0 + (score - x0) * (y1 - y0) / (x1 - x0)
aps = np.clip(aps, 0, 100)

Recent attempts feed assessment scores, then skill-category averages. Bands run from Foundation to Elite; APS remains on a 0–100 scale.

What I checked—and what still needs work

13 functional checks pass: bounds, monotonicity, score direction, recent-attempt weighting, cohort fallback, benchmark counts, row-order invariance, and constant-score handling.

In a synthetic 1% noise experiment, the mean absolute score change was 0.45 RPS points and 0.45 APS points. This is one controlled sensitivity check, not a claim about real athlete outcomes.

A deliberately separated-cohort stress test found a 23.82-point RPS jump at the 30-observation threshold. APS also needs a review of lower-is-better anchor calibration. Making these limitations visible is part of the analytical work.

What I would improve next

No match-outcome labels were available to validate game-performance prediction. The proposed production handoff ports deterministic scoring to Elixir and checks it against Python fixtures; the public repository does not establish that this deployment occurred.

Evidence & reproducibility

Public evidence includes Python modules, 13 functional checks, and reproducible synthetic stress probes. These verify selected software properties, not athletic validity or production deployment.
