Athlete Scoring — Sogility

Coaches were comparing athletes on 40-plus assessments that did not point the same direction, and small groups made a raw percentile jump around.

A scoring pipeline that turns those assessments into one 30–99 score, with a dashboard for peer benchmarks and progress over time.

40+ assessments30–99 scalePercentile benchmarksRelational model
PythonData modelingDashboards

The problem

Some tests are “higher is better” and some are the reverse. A team with a handful of athletes cannot use a raw rank without the score swinging when one person joins or leaves.

Approach

  • Normalized each assessment in the correct direction.
  • Benchmarked athletes with percentiles, and smoothed scores when the comparison group was small.
  • Mapped the result onto a shared 30–99 scale so tests can be read together.
  • Stored athlete profiles and assessment history in a relational model that feeds the dashboard.

Result

Coaches can compare athletes on one scale and follow the same athlete across test dates, instead of reconciling spreadsheets that each use a different unit.

What this leaves open

This writeup is from the engagement. There is no public repository, because the assessment file and athlete records are not mine to publish.
